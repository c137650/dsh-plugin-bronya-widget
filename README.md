# dsh-plugin-bronya-widget

在 DSH 主会话右下角挂一个像素风的布洛妮娅。她不说话、不接受点击,只是在那里过她的一天。

## 她会做什么

| 她的状态 | 画面 |
|---|---|
| 清醒 + 语音交互中(麦克风或播报) | 拿起耳机说话 |
| 清醒 + 跟你说话 | 敲键盘 |
| 清醒 + 闲着没人理 | 摸鱼打游戏 |
| 清醒 + 她自己在跑自主活动,又被你搭话 | 生气敲键盘 |
| 清醒 + 活动在跑,但没人理她 | 敲键盘(在忙自己的) |
| 吃饭 | 端着碗往嘴里送 |
| 吃饭时被打扰 | 举着筷子、皱着眉喊出来 |
| 睡觉 | 躺在床上盖着被子,冒出 Zzz |
| 睡觉时被打扰 | 撑着脸、半睁着眼,一副没睡醒的样子 |

"被打扰"= 她在吃饭或睡觉的时候,舰长在对话里开了口。

**什么时候结束**:不看固定秒数,看那个会话还活不活跃。
舰长刚说完话、或者布洛妮娅还在生成(一轮对话从 `turn/start` 到 `turn/end`),
她就一直保持被打扰的样子;会话闲下来再过 18 秒才回到原来的动画。
舰长在输入框里打字也算 —— 这一条宿主看不到输入框,由客户端自己盯着 `input` 事件。

**正在播报也算**:语音模块把回答念完之前,画面不会回到吃饭/睡觉。
播报走的是 `AudioContext` + `AudioBufferSourceNode`,没有 `<audio>` 元素、
插件也没有对外暴露 speaking,所以客户端包了一层 `createBufferSource().start()`
来数"现在有几路声音在响",靠 `ended` 退回。不改语音插件的任何行为;
哪天它换成 `<audio>` 播放,这里要跟着换检测方式。

**麦克风/播报也算**:语音交互进行中,她就是"在听你说话"的姿势。判断条件是**或**,
四个信号任意一个成立就算:

| 信号 | 怎么认的 |
|---|---|
| 麦克风真的开着 | 浏览器里拿到了音频流(`getUserMedia({audio})` 开了、轨道还没 stop) |
| 麦克风开关打开着 | 语音模块写在 `localStorage` 的 `s2s.voice.mic` |
| 播报开关打开着 | 语音模块写在 `localStorage` 的 `s2s.voice.enabled` |
| 此刻正在播报 | `AudioContext` 里有 `AudioBufferSourceNode` 在播 |

两个开关都是语音模块自己的键,这里只读不改;轮询时顺带读一次,所以舰长随时切开关都能立刻生效。
摄像头那条路走本地 bridge、不经过 getUserMedia,所以不会混进来。

这一条优先级高于敲键盘和打游戏,但只在清醒时生效——睡觉/吃饭有各自被打扰的表情。

## "活动正在执行"怎么认

life 插件的后台自主活动跑在 `life-<uuid>` 的会话里(展开细节的对话是
`life-detail-*`,那算正常聊天,不算活动)。插件靠会话前缀 + 会话是否在跑来认:
`life-*` 且不在 `life-detail-*` 下的会话正在跑 = 活动执行中。

这样不需要 life 插件额外写状态文件,也不需要猜心跳间隔。

## 状态从哪来

唯一来源是 `dsh-plugin-life` 的心跳落盘文件:

`%DSH_HOME%/dsh-plugin-life/status.json`

- `phase`:`wake` / `eat` / `sleep`,life 每 4 分钟更新一次;
- 文件超过 15 分钟没更新(比如 life 没跑),就按 `today.segments` 自己推算此刻该是什么阶段;
- 两样都没有(没装 life)——不显示角色,也不报错。

本插件不复制那套作息算法:作息怎么排是 life 的事,这里只负责"读 + 画"。

## 接口

- `GET /bronya-widget/state` → `{ ok, phase, fresh, chat, activity, recentUser, life, disturb, now }`
  - `chat`:主会话正在生成(`turn/start` 之后、`turn/end` 之前,不含 life 的后台活动);
  - `activity`:life 插件的后台自主活动正在执行;
  - `recentUser`:舰长刚说过话(18 秒宽限期内);
  - `disturb`: `{ kind: 'eat' | 'sleep', since, busy }` —— 只在"该显示被打扰"时出现;
- `GET /bronya-widget/sprite/<state>.webp` → 对应状态的循环动图
  (`wake` / `angrytype` / `game` / `voice` / `eat` / `angry` / `sleep` / `wakeup`)。

客户端每 1.2 秒取一次 state,状态变了就换一张 `<img>`。

## 美术

`assets/` 里是八张带透明的循环 WebP 动图,尺寸 144×144,由素材抽帧生成:

| 状态 | 素材 |
|---|---|
| wake | `E:\绘画训练\jimeng-...2100-...人物坐....mp4`(即梦,敲键盘) |
| angrytype | `E:\绘画训练\jimeng-...5964-...`(即梦,生气敲键盘;只取第 72 帧之后那段) |
| game | `E:\绘画训练\jimeng-...9779-...`(即梦,上班打游戏;只取第 30 帧之后那段) |
| voice | `E:\绘画训练\jimeng-...3930-...`(即梦,拿起耳机说话;只取第 62–103 帧) |
| eat | `E:\绘画训练\jimeng-...3643-...人物捧....mp4`(即梦,捧碗) |
| angry | `E:\绘画训练\angry.gif`(举筷子) |
| sleep | `E:\绘画训练\viberot-gif-84469d3b.gif`(躺着睡) |
| wakeup | `E:\绘画训练\viberot-gif-344fba32.gif`(撑脸犯困) |

素材里一段视频往往包含两种动作(前面正常敲键盘、后面才是生气/打游戏),
`SOURCES` 里的 `from` 就是"从第几帧开始取",用 `trim=start_frame=` 切掉前面那段。

生成器在 `tools/build_sprites.py`(需要 numpy、Pillow 和 ffmpeg):

```sh
cd tools
python build_sprites.py            # 全部重建
python build_sprites.py wake       # 只重建一个状态
```

抽帧缓存在 `tools/src/<state>/`,预览图落在 `tools/preview/`。素材换了就改脚本顶部的
`SOURCES`,重跑,`assets/` 会自动更新。整套东西都在插件目录里,不依赖工作区。
上一版动图和上一版脚本留在 `tools/backup-<时间戳>/`,哪天想退回去直接拷回来。

## 安装

```sh
dsh plugin --profile desktop add <本目录绝对路径>
```

或者手工:profile 的 `package.json` 里加 `link:` 依赖 + `dsh.profile.bundles` 条目,
并在 `node_modules` 里建一个同名 Junction 指向本目录。改完重启 DSH。

## 已知取舍

- 全局显示,不区分会话——所有会话的右下角都有她。
- 可以拖:按住拖到任意位置,松手后记住(`localStorage`);双击回到右下角。位置存在
  `localStorage` 的 `dsh-plugin-bronya-widget:pos` 里,想复原就清掉这个键。
- 默认尺寸 84×84,默认贴在右下角 `margin: 12px`——再大就会压住输入框右下角的发送/中止键。
  想改就改 `client/client.js` 顶部的 `SIZE` / `MARGIN`(改完刷新页面,没生效就重启 DSH)。
- 睡觉那张是躺着,视觉上比站姿矮,这是素材本身的构图,不是缩放错了。

## 抠图的坑

素材是 AI 生成的像素风/Q 版动图:白背景和人物身上的白几乎同色,背景还带一层软边、
压缩噪点(强边长出来的那种蚊式噪声),偶尔还有平台水印。

**逐帧各抠各的必然会闪。** 阈值正好落在软边和噪点里,边界每一帧都要挪几像素,
播放时就是背景里那一圈东西忽隐忽现。旧版试过用"每帧都像背景色才一律抠掉"来救,
但清到的只是完全静止的残留,清不到会抖的那条带子。

现在的做法(`tools/build_sprites.py`):

1. **先在中间分辨率上抠**,输出的 2 倍(960 → 288)。BOX 缩放把噪点平均掉,
   一像素的软边被压到不到一像素,"边界在哪"这件事本身就稳了;
2. 逐帧从**画面四边**洪水填充,只留最大连通块——水印、碎屑顺手清掉;
3. 整段取**共识轮廓**(逐帧掩码的时间多数票),再做一次闭运算补小洞。
   背景层的时间噪声实测 std 只有 1 左右,所以这张形状定下来就真的不动;
4. **挖真缝**:被人物包住、整块颜色又几乎和背景一样的区域,是头发和背之间那种
   真背景缝,要挖掉。判据是这块的背景距离中值要小到 9 以下——皮肤高光、被子
   自己的白都够不到这个门槛,所以不会被挖穿。挖完的位置在柔边前后各压一次 0,
   不然 1px 的模糊会把缝又糊上一层白;
5. **柔边也来自这张形状**(一次 1px 模糊),不是逐帧重新判定,所以柔边是恒定的;
6. 只有"这一帧这里实打实多了块前景"才补 alpha:离背景色 150 以上、并且面积够大。
   手伸出去、筷子甩开这类真动作算数,软边上 0.3↔0.7 的摇摆进不了这个门槛;
7. **逐帧亮度对齐**:素材开头几帧整体偏暗(即梦那条 wake 素材首帧比后面暗 4% 左右),
   按主体区域的亮度对齐到整段中值,循环播放时就不会"某一帧突然暗一下";
8. 缩放走 float **预乘 alpha**,颜色只在 alpha 内部参与平均,不会出白边。

参数都在 `SOURCES` 里:

| 参数 | 管什么 |
|---|---|
| `tol` | 背景往外扩到哪儿。睡姿那张的被子本身就是白的,必须收紧到 18,否则洪水会顺着被子灌进去 |
| `strong` | 什么算"这一帧确实有东西"(补 alpha 的门槛) |
| `fill` / `blur` | 补洞半径 / 柔边半径 |
| `gap` | 挖"真背景缝"的门槛(0 = 不挖)。睡着那张被子内部全是白,所以关掉 |
| `gain` | 逐帧亮度对齐,默认开 |

体检指标是"相邻帧 alpha 变化 >0.4 的像素数",越小越稳(144×144 一共 20736 个像素)。
这一版:wake 19442→3780,eat 18552→4570,angry 47131→20814,sleep 15259→750,
wakeup 1431→379。angry 剩下的主要是素材本身胳膊和筷子在动,不是抠图问题。

调完一定要看 `tools/preview/` 里那张对照图:上排深色底能看出残留,下排洋红底能看出
被啃掉的地方(白被子挖成透明洞、水印没掉干净,都在这两张图上一眼可见)。
